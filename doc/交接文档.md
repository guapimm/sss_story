#### 4.1 ★ 新发现的诊断陷阱：失败时读到的是**上一轮**产物（已修）

**这是本轮最重要的方法论修复 —— 它会让 D-16 的整个判断失效。**

| | |
|---|---|
| 现象 | 拿 `_diag_skeleton_16.json` 里的骨架复算 `_mentions`，得到"两个地名里有一个其实**能匹配上**"这种**自相矛盾**的结论 |
| 根因 | `persist_skeleton` **只在成功时**写盘（`books.py:248`）。失败后读 `skeleton_ref`，读到的是**上一轮成功跑出来的旧骨架** —— 实测 `data/artifacts/books/16/skeleton/v001.json` 的 mtime 比 `bible.md` 早了 **13 万秒**（约 1.5 天） |
| 危害 | 违例消息说的是当轮新骨架，文件里存的是旧骨架。**两者不是同一份产物** → "真缺失 vs 措辞未命中"的判断整体失效 → 极易据此去改一个**本来正确**的匹配器（我这次就差点改了） |
| 修复 | `SkeletonResult.last_skeleton` 回传当轮产物 → 图失败分支落盘到 **`books/{id}/debug/skeleton_failed_v{v:03d}.json`** → state 只传 `last_skeleton_ref`（遵守契约规则 5，State 不得含大文本） |
| 为什么放 `debug/` | 它**不是业务产物**，任何节点都不会读它续跑。防"上一轮失败的东西变成这一轮的输入" |
| 回归 | 3 个新测试：当轮产物可拿到 / 成功时不带诊断包袱 / key 在 `debug/` 下且与业务 key 不同 |

> **教训**：诊断代码本身也会有 bug，而且**诊断错了比不诊断更糟** ——
> 它会把正确的东西"证明"成错的。凡"读产物文件做判断"的地方，
> 都要先问一句：**这个文件在这条路径上真的被写过吗？**

## 5. 我犯过的方法论错误（务必避免重蹈）

**我用同一本书（「旧档案馆值夜人」）反复调校验器十几次。**
那是过拟合的入口：阈值会被调成"只对这一本书成立"，换一本书立刻失效，
而我看不出来。用户明确指出了这一点。

对策已固化为 **D-16**：

| 出现书数 | 判定 | 动作 |
|---|---|---|
| ≥3 本 | 通用缺陷 | 必须修在链路/校验器里 |
| 2 本 | 待观察 | 记录，看下一批 |
| **1 本** | **单书特例** | **只记录，不放宽校验器** |

关键在最后一行：**单书失败不得直接触发"放宽阈值"**。
要先问"是校验器太严，还是这本书真的不合格"。

## 9. 密钥管理（★ 重要）

- 密钥在 **`.env`**（已被 `.gitignore` 忽略，**不会入库**）
- CLI 启动时自动 `load_dotenv()`；**真实环境变量优先**，文件不覆盖
- 模板见 `.env.example`
- 当前用的是小米 MiMo 官方 Token Plan：
  - endpoint `https://token-plan-cn.xiaomimimo.com/v1`
  - 模型 `mimo-v2.5`（单模型策略，与旧项目生产一致）

**MiMo 的实测特性**（已写进 `config/providers.toml` 注释）：

| 特性 | 实测结果 |
|---|---|
| 原生 JSON 模式 | ✅ 支持（`response_format={"type":"json_object"}`），加上后严格解析直接通过 |
| **关闭思考** | ❌ **无法关闭**（`enable_thinking:False` / `thinking:False` 都被服务端忽略） |
| `reasoning_effort` | ✅ 认 `low` / `high`；`minimal` 返回 400 |
| 思考占比 | 正文 ~20%；**抽取任务 89~92%** |
| 缓存字段 | 未观察到 → `usage_source=partial`，成本按保守全 miss 计 |

→ 因此抽取节点声明 `thinking = "minimize"`（取最低档）而不是 `forbidden`
（后者要求真能关掉，MiMo 不满足，会导致路由抛 `NoCapableModelError`）。

**思考强度 high 的质量结论**（14 次真实调用 A/B 实测，09-13）：

| high | 4 | 0.732 | 3918 |

→ 09-13 结论是保持 `low` 为默认。

`reasoning_effort = "high"`，抽取类（`minimize`）保持 `low` 防截断。
`NodeRequirement` 新增 `reasoning_effort` 节点覆盖字段（仍走 toml 能力声明，
