# 决策 D-16：多书测试是校验器的**必要**验收方式

> 记录日期：2026-09-13
> 触发：项目负责人指出「进行测试的时候尽量多个书测试，不要最后成了专门的优化」

---

## 问题（我实际犯的错）

在打通真实链路的过程中，我用**同一本书**（「旧档案馆值夜人」规则怪谈）
反复跑了十几次来迭代校验器：

| 轮次 | 现象 | 我的动作 |
|---|---|---|
| 1 | `他人` 被当成人物代词「他」 | 收紧代词判据 |
| 2 | 世界观 138 字 < 200 阈值 | 改为总字数下限 |
| 3 | `rules` 里混进 `era：…` | 加错位校验器 |
| 4 | 骨架"未落实新势力"（实为措辞改写） | 加容错匹配 |
| 5 | 又"未落实"（实为长括注淹没主名） | 改主名优先匹配 |

**每一轮都是针对那一本书的具体措辞去调阈值。** 这条路的终点是：
校验器被调成"只对这一本书成立"，换一本书立刻失效 —— 而我看不出来。

这与旧项目「只在小样本上验证就上线」是同一类错误。

---

## 决策

### 1. 校验器的验收标准是**跨书一致**，不是单书通过

```
uv run python scripts/multibook_e2e.py
```

用 6 本**题材与规模都差异极大**的书跑完整规划链路：

| id | 题材 | 全书章数 | 特点 |
|---|---|---|---|
| 11 | 规则怪谈 | 400 | 现代都市、规则体系（已充分测过，作基线） |
| 12 | 仙侠修真 | 800 | 古典、境界体系、势力众多 |
| 13 | 都市言情 | 200 | **无战斗**、关系驱动 |
| 14 | 硬科幻 | 600 | 太空、科技、非人类实体 |
| 15 | 历史架空 | 300 | 朝代、官职、战争 |
| 16 | 现代悬疑 | 150 | 小规模、单线 |

### 2. 失败的归类判据

| 出现书数 | 判定 | 动作 |
|---|---|---|
| **≥3 本** | ★ **通用缺陷** | 必须修在链路/校验器里 |
| 2 本 | 待观察 | 记录，再看下一批 |
| 1 本 | **单书特例** | **只记录，不放宽校验器** |

关键在于第 3 行：**单书失败不得直接触发"放宽阈值"** ——
那正是过拟合的入口。要先问"是校验器太严，还是这本书真的不合格"。

### 2.1 ★ 补充（2026-09-16）：判据依赖**正确的分类**，否则阈值判了也白判

这条决策有个前提，我原先没写出来：**"几本"必须数对**。

实测踩到：`_classify` 按元组顺序匹配，短关键词 `新地图` 排在
`未提及本卷新地图` **前面**，于是**骨架侧**违例被归类成**台阶侧**标签。
后果：

    实际 3 本（13/15/16）→ 报表上看起来像 2 本（+ 后来才发现第 3 本）
    → 差点按"2 本 = 待观察"放过一个必修缺陷

**纠正手段（可复制）**：`multibook_e2e.py` 是**遇错即返回**的，因此

| 阶段状态 | 标签只可能来自 |
|---|---|
| `volume_ok=False` | `gate_issues`（台阶侧） |
| `volume_ok=True` + `skeleton_ok=False` | 骨架 `violations` |

书 13/15 是后者，标签却写着 `volume:*` —— 一眼看出分类错了。
脚本：`scripts/diag_d16_threshold.py`。

> **规程**：数"几本"之前，先验证**分类本身**是对的。
> 用**阶段状态**（谁失败）交叉校验**标签**（说谁失败）——
> 两者矛盾时，先修分类，再判阈值。

### 2.2 ★ 补充：判据还依赖**产物属于本次运行**

实测第二次踩到：失败时 `persist_skeleton` 不写盘，诊断去读产物文件
拿到的是**上一轮**的旧骨架 → 复算匹配器得到自相矛盾的结论，
并**凭空造出一个不存在的缺陷**。
详见 `doc/交接文档.md` §4.1/§4.5。

> **规程**：凡"读产物文件做判断"，先确认**这个文件属于本次运行**
> （mtime / 诊断产物自带 `*_source` 标记）。

### 2.3 ★ 补充：D-16 约束的是**调阈值**，不是"发现明确 bug 也不修"

本轮区分了两种改动，容易混为一谈：

| 类型 | 要数据吗 | 例子 |
|---|---|---|
| **调阈值 / 放宽判据** | ★ **要**（D-16 管的就是这个） | LCS 4→3、占比下限 15%→14% |
| **修实现与声明不一致** | **不要** | 「以 ID 为准」没兑现；`places` 字段不存在导致要求无处落 |

后一类是**确定性错误**（代码没做到它自己文档说的事），
修它是"让代码符合声明"，不是"把门槛降低迁就数据"。
本轮修的两处（ID 优先级、`places` 字段）都属此类。

### 3. 为什么这也顺带解决了「题材抽象」的验证问题

6 本书里有 3 本（言情/科幻/历史）的词汇表**在当前枚举里根本没有对应值**：

- 言情：需要 `恋人`/`夫妻`/`同事`/`前任` 这类关系；当前 20 个关系词里
  **11 个是武侠仙侠专用**（师徒/结拜/道侣/同门/叛变/世仇…）
- 科幻：需要 `星舰`/`AI`/`殖民地` 这类实体；实测 `AI`/`星舰`/`公司`
  **全部被拒**（`normalize_entity_kind` 抛错）
- 历史：需要 `官职`/`朝代` 这类概念

因此多书测试**同时**是题材抽象（Profile + 语义轴）的验收手段 ——
抽象做对了，6 本书都能过；做错了，只有原来那一本能过。

### 4. 与「质量优先」的关系

多书测试不替代真实质量评估（那是 P5 用打分卡 + 人工判读做的），
它管的是**链路鲁棒性**：同一套校验器换题材后还成立吗。

两者都需要，但解决不同问题：
- 多书测试 → "换一本书还能跑通吗"
- 打分卡 + 人工 → "写出来的东西好看吗"

## 复现

```powershell
# 全部 6 本（清掉旧产物重跑）
uv run python scripts/multibook_e2e.py --clean

# 只跑某几本
uv run python scripts/multibook_e2e.py --books 12 13
```

产出 `doc/research/multibook-e2e.json`：每本的阶段结果 + 失败分类统计。
