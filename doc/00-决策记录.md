### D-13 · 并行流水线架构（三级流水线 + 协调器）

| 项 | 内容 |
|---|---|
| 问题 | 圣经完成后开始骨架；骨架第一批完成即并行补细纲；第一章细纲确认后立即开始正文，同时后续细纲继续生成。如何建模？ |
| 选定 | **三级流水线（骨架 → 细纲 → 正文），阶段内严格串行、阶段间并行**；由**纯 Python 协调器**（asyncio）管理队列与闸门；**LangGraph 图作为「工作单元」被协调器调用**（骨架批次图 / 细纲批次图 / 单章图） |
| 理由 | ① 若做成单图的两个分支，`interrupt()` 会**冻结整个图** → 确认首章细纲时骨架/细纲生产也被冻住，**用户要的并行就没了**；② 每单元一个 `thread_id` → 崩溃恢复是**单元级**的，更精确；③ 人类确认变成"该 worker 等待"而非"全图暂停"；④ 与调研结论一致：「用确定性 custom workflow，不要 supervisor 自由路由」 |
| 关键约束 | **正文生产严格串行**（一次一章）。理由：旧项目实测并行起草 4 章时，后写章按**同一时刻账本**构建上下文 → 看不到前章记忆；且出过 pregen 与 serial **双写同一章**。章间并行省时有限，但损伤连贯性，与「质量优先」冲突 |
| 影响 | 阶段边界与工作单元边界 = checkpoint 边界；协调器持有队列与"谁领先"逻辑；**协调器不含领域逻辑**（只做编排） |
| 状态 | ✅ 已确认 |

| 建议默认 | **全书单一递增 int 章号**（1..N），废弃旧项目的 `vol*10000+idx` 全局号与卷内号双轨制 |
