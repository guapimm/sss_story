## 产品目标

面向普通 Windows 用户，提供可自定义安装目录的桌面应用和漂亮、易用的 GUI。用户可在管理界面
下载或导入本地模型权重，管理模型和推理设置；NVIDIA GPU 优先，无法使用时回退 CPU；同时支持
云端模型。安装位置、用户数据和模型权重必须分开管理，卸载/升级应用不能误删用户数据或权重。

以上是产品要求。技术实现仍需验证：Tauri/Rust 桌面壳 + Python sidecar 是候选建议，尚未拍板；
本地推理运行时、权重格式/来源、GPU 能力检测与回退策略也需在对应阶段实测后确定。

## 已完成：PG-0 与 PG-1

PG-0 在非 editable wheel 安装中证实了原先的安装态故障：`config/` 未进入 wheel；`REPO_ROOT` 与
prompt 路径锚点错误；`.env` 无合法用户位置；`arch-check` 在缺少测试目录时静默失败；doctor
扫描缺失源码时假通过、检查项缩水，并把数据库写入安装目录；`flows` 在资源缺失时返回空且退出码为 0。
归纳根因是资源未打包、路径依赖源码树、失败被静默处理。PG-0 原始复现记录已通过 Git 历史
`dcfd9a6` 中的 `doc/10-PG0打包取证记录.md` 保留。

PG-1A/1B/1C 已全部完成：wheel 通过 `force-include` 带入 64 项 config 与 3 个 prompt；资源定位支持
源码树和 wheel 安装态；安装态数据目录使用用户目录，doctor 只读且安装目录零写入；doctor 报告
保持完整，缺资源时显式报错。PG-1C 的变异四连通过，最近交接记录报告 1133 passed / 15 skipped、
doctor PASS、arch-check exit 0。阶段实施细节和取舍可从 Git 历史 `dcfd9a6` 的 `doc/11-PG1资源路径修复方案.md`
追溯；当前状态以 `doc/交接文档.md` 顶部最新快照为准。

关键教训：安装态必须用非 editable wheel 或最终发布产物验证；源码树测试和 doctor 全绿不能证明
资源随包、用户目录可写、静默失败可见。资源缺失必须报错，安装态检查不可因源码缺失而假通过；
doctor 不得创建目录或数据库。实现中保留的边界：config 数据留在仓库根、由 wheel 构建映射
进包（避免与 `storyforge/config.py` 包内命名冲突）；空命名空间可合法返回空集合，但缺失资源必须报错；
`REPO_ROOT` 仍服务开发态路径，不可为了安装态全局删除；只有安装态切换用户数据目录，避免搬动开发机
真实数据；`scripts/` 中相对仓库根的路径属于开发工具，无需打包改写。

## 打包线下一阶段：PG-2 最小安装包冒烟

本阶段只验证可回滚的最小安装壳，环境为干净 Windows，**没有 Python 或 uv**：用户可自定义安装目录；
应用可启动；离线 `doctor` 与 `flows` 可用；用户数据落在独立的数据目录，且应用安装/升级不覆盖数据。
不把本地模型或云端模型接入纳入本阶段验收。

PyInstaller 仅作为条件性候选，需先验证依赖与发布体验后才采用。若使用 PyInstaller，冻结路径解析
必须单独识别 `getattr(sys, "frozen", False)` 并覆盖 `sys._MEIPASS`；不得把临时解包目录当成用户
数据或模型目录。Tauri/Rust + Python sidecar 也是候选方案，尚未通过原型验证或作为最终架构决策。

建议按以下顺序逐阶段验收：

1. **PG-2 安装壳**：自定义安装目录、离线 doctor/flows、数据目录隔离。
2. **PG-3 模型管理**：管理界面支持本地权重下载与导入，存入独立模型目录。
3. **PG-4 本地推理**：NVIDIA GPU 优先；不可用时 CPU 回退。
4. **PG-5 云端模型**：配置并使用云端模型，凭据保存在用户级安全配置。
5. **后续 GUI 完整化**：完成面向普通用户的漂亮、易用的完整工作流界面。

这些是阶段建议，不代表架构或发布工具已经拍板。目录职责至少分为：

| 内容 | 生命周期与位置 |
|---|---|
| 应用程序 | 用户选择的安装目录；由安装器升级/卸载管理 |
| Storyforge 用户数据 | Windows 用户数据目录；不随程序升级删除 |
| 本地模型权重 | 独立的用户可配置模型目录；不放安装目录，不随应用卸载删除 |
| 云端模型凭据 | 用户级安全配置；不得写入程序目录或仓库 |
