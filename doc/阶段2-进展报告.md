uv run storyforge learn-map accept   --book-id 31 --mappings "函数"    # L-2 逐条
uv run storyforge learn-map edit     --book-id 31 --term "函数" --replacement "本命功法"
uv run storyforge learn-map reject   --book-id 31 --term "循环"
uv run storyforge learn-map history  --book-id 31
uv run storyforge learn-map rollback --book-id 31 --revision 4

## 五、过程中值得记录的教训

### ★★ 规则 22 曾是**无效契约**（本轮最重要的一条，变异测试拆穿的）

规则 22（查"函数体引用未定义名"）**写完时 `pytest` 全绿，但它抓不到它要抓的缺陷**。
`scripts/mutate_rule22.py` 拆穿后深挖，发现原实现有**两个互相掩盖**的 bug：

  · `_collect_bound` 对**整棵树** `ast.walk` → 把"函数体内的 import"当成模块级绑定
  · `_check_scope` 用 `ast.walk(scope)` → 把嵌套函数体的 Name 拿外层可见集判

**bug 2 恰好被 bug 1 掩盖** —— 泄漏把名字塞进了模块级可见集，于是"看起来"可见。
两 bug 相抵，**删掉真依赖照样通过**。

⇒ **一个"抓不到问题"的契约测试等于没有。** 已重写为 stdlib `symtable`
（CPython 自己判定 local/free/global 的模块）+ **36 条构造样本电池进 CI**
（14 条"必须报" + 22 条"必须放行"）。

★ 修的过程中**我自己的探针复现了同一个 bug**（第一版也递归子表收模块级绑定），
自证漏报 2 个案例。**"只收模块级"必须真的只看顶层表。**

★ **教训**：判定逻辑复杂的规则，**它自己就是被测对象**。只靠"跑一遍现有
`src/` 没报错"确认，则规则**退化成永远放行**也照样绿灯 —— 本项目**已第二次**应验。

**移植的六条规则**（逐条来自旧项目并加测试钉住）：

1. **间隔单位是「章」不是「天」** —— 读者的遗忘曲线由阅读进度决定

3. **高潮 / Boss / 情绪章不注入** —— 避免打断场面
4. **上限自适应** —— 有新知识点 → 1；没有 → ≤3
5. **最紧急优先**（按 `next` 升序）—— 防冷门卡长期轮不到
6. **用了才推进，没用就顺延**（`max(next, now) + delay` 且不记复习）
