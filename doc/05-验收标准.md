# 05 · 验收标准

> **用途**：定义可执行的验收命令与判定阈值。每期结束时逐条执行并记录。
> **原则**：**可复现、可量化、可对比**。凡是"读起来顺了""感觉变好了"都不算验收。
> **对比基线**：旧项目生产库实测值（见 `research/00-evidence-baseline.md`）。

---

## 1. 一期总验收（P5 结束时）

### 1.1 功能验收

```bash
# 全流程端到端（standard 档 25 章，story 模式）
uv run python -m storyforge.cli run-book \
    --topic "一个能自动改写规则的值夜手册" \
    --genre suspense --scale standard --chapters 25
```

**必须满足**：

| # | 条件 | 验证方式 |
|---|---|---|
| 1 | 25 章全部产出，无人工干预（除 3 个人工确认点） | 检查 `chapters` 表 25 行 `status='committed'` |
| 2 | 无 0 分章节（审校本身不失败） | `SELECT COUNT(*) FROM chapters WHERE score = 0` = 0 |
| 3 | 打分卡可复现 | 同一章重复跑打分卡，结果**逐字节一致** |
| 4 | 所有卷的升级台阶均已规划 | `volume_plans` 行数 = `total_volumes`；无 `blueprint='missing'` |
| 5 | 中断后可恢复 | 主动 kill 进程，重启 `resume`，不重跑已完成阶段 |

## 2. 分期验收

### P0 · 地基

```bash
uv sync                                       # 成功
uv run pytest                                 # 全绿
uv run python -m storyforge.cli doctor        # 自检通过
```

| 检查项 | 断言 |
|---|---|
| 依赖隔离 | `grep -r "langgraph" src/storyforge/domain/` **返回空**（领域层零框架依赖） |
| 外键存在 | `PRAGMA foreign_key_list(<每张表>)` 非空 |
| 配置类型化 | 故意写错配置 → 报明确错误（非静默降级） |
| 配置单一优先级 | 不存在"某处写了却被静默覆盖"的路径 |
| 测试隔离 | 每个测试独立临时 DB；连续跑 2 次结果一致 |
| 观测字段 | `LLMCallRecord` 含 `finish_reason` / `context_breakdown` / `prompt_prefix_hash` / `cached_tokens` |
| 无 vendored 依赖 | 仓库内无 `_pylibs` 类目录 |

### P1 · 领域模型

```bash
uv run pytest tests/unit -v                   # 全覆盖
uv run pytest tests/unit/test_injury_thresholds.py -v
uv run pytest tests/unit/test_chapter_number.py -v
uv run pytest tests/unit/test_entity_types.py -v
uv run python -m storyforge.cli validate-structure --book-json <书23大纲>
```

| 检查项 | 断言 |
|---|---|
| 阈值表穷尽 | 遍历 `InjurySeverity × InjuryKind` 全组合，**每个都有阈值**（防旧项目"最重的伤不催"） |
| 未登记 severity | **不静默逃逸**（抛错或显式 fallback + 告警） |
| 章号单一 | `since_ch` 与 `current_chapter` 同口径；跨卷不产生 10011 类错误 |
| 枚举单一来源 | severity 的 Enum → prompt 文本 → 解析器**三者同源**（有测试断言） |
| 势力类型 | `势力` 与 `组织` **合并映射**，不产生"其他"降级 |
| 地点归一 | `长明楼三层值班室` / `长明楼三楼档案科资料室` → 同一 parent |
| 扩张度闸门 | 书 23 的卷分配 → **阻断** |
| 里程碑密度 | 202 章真空 → **阻断** |
| 伤势调度 | 预热序列生成；`scene_ref` 必须指向真实 `SceneBeat` |
| entry/exit 连续性 | `exit[N] != entry[N+1]` → 检出 |
| `BeatType` 含 heal | `HEAL` / `RECOVERY_PREP` 是合法节拍 |
| **换图正向机制** | 规划内的换场**不被判违规**；规划外的换场才被检出 |
| 4-gram 口径 | 复现 baseline p50 6.2% / 9.8% |
| 缺省即不通过 | 无法评估返回 `None`，**不返回 0** |

| 打分卡可复现 | 同输入 → 逐字节相同输出 |

### P3 · 规划图

```bash
uv run python -m storyforge.cli plan --topic "..." --scale standard --chapters 25
```

| 检查项 | 断言 |
|---|---|
| 全卷台阶 | `volume_plans` 含**全部卷**；每卷 `new_locations`/`new_factions`/`antagonist` 非空 |
| 台阶差异化 | 各卷 `antagonist` 两两不同；`escalation_from_prev` 非模板句 |
| 闸门阻断 | 不满足扩张度 → **阻断**并进入增量补缺 |

| 伤势节拍 | 细纲含 `health_beats`；指向真实 `SceneBeat` |
| 断点恢复 | 中断 `resume` 不重跑已完成阶段 |
| 人工确认 | 3 个 `interrupt()` 点可暂停/恢复 |

### P4 · 单章闭环

```bash
uv run python -m storyforge.cli write --book <id> --chapter 1
```

| 检查项 | 断言 |
|---|---|
| 打分可复现 | 同一章重复打分 → 逐字节一致 |
| 审校产出率 | 触发审校后 `revised_content` 非空率 **≥80%**（旧项目空转） |
| 审校结构约束 | `issues` 非空 → `revised_content` 必填（schema 强制） |

| state 引用化 | 图 state 中**无正文字符串**（只有引用 ID） |

## 3. 质量回归测试（golden fixtures）

**目的**：防止"改一处、坏一处"。

```
tests/golden/
├── fixtures/
│   ├── chapter_01.json          # 固定输入（圣经+细纲+状态）
│   ├── chapter_01.expected.json # 期望的打分卡输出（零 LLM 部分）
│   └── ...
└── test_scorecard_golden.py
```

**规则**：
1. **零 LLM 部分必须有 golden 测试**（打分卡、lint、闸门、调度器）—— 这些是确定性的，可精确比对
2. **LLM 部分不做逐字节比对**（不可能稳定），改为**断言性质**：
   - `volume_plans` 满足 schema
   - 审校输出满足结构约束
   - 重试上限被遵守
3. golden 文件更新必须**显式说明原因**（防止悄悄放宽断言）

## 4. 反模式检查（AST 级约束）

这些是用**机器检查**防止旧项目问题复发的硬约束：

| # | 检查 | 防的是什么（旧项目/ LangGraph 实证） |
|---|---|---|
| 1 | `domain/` 不得 import `langgraph` / `langchain` | 框架侵入业务逻辑 |
| 2 | `scorecard/` 不得 import `infra.llm` | 打分卡必须零 LLM（可复现） |
| 3 | `domain/` 与 `graph/nodes/` 不得出现 `book_kind` / `is_story` 判断 | 旧项目门面外仍有 30+ 处直读模式 |
| 4 | 任何模块不得出现 `model == "..."` 硬编码 | 旧项目"思考预算"策略不具跨模型鲁棒性（mimo 0% vs qwen 91.4% 空输出）；且 DeepSeek 模型名已过期（`deepseek-chat` 2026-07-24 停服） |
| 5 | `graph/state.py` 的 State 字段不得含 `str` 型大文本字段 | 旧项目把 outline/content 塞进 JSON 列；LangGraph checkpoint 官方承认 200 轮 **5.3 GB** |
| 6 | 每张表必须有 `FOREIGN KEY`（除根表），且连接时必须 `PRAGMA foreign_keys=ON` | 旧项目 0 FK，靠人工清单清理，漏过 6 张表；SQLite 默认**不强制** FK |
| 7 | 章号字段类型必须为 `int` 且单调递增 | 旧项目 `vol*10000+idx` 双表示导致 P0 事故 |
| 8 | 枚举必须有唯一来源（不得在多处重复定义） | 旧项目 severity 代码 5 档 / prompt 3 档 → **最重的伤不催、轻伤催得最凶** |
| 9 | 不得有以业务实例命名的模块（如 `book23_*.py`） | 旧项目 `book23_ultra_repair.py` / `book25_ultra_repair.py` |
| 10 | 单函数不得超过 200 行；单文件不得超过 800 行 | 旧项目 `_commit_chapter` 1,239 行、`pipeline.py` 8,607 行 |
| 11 | 测试文件不得在模块级修改 `os.environ` | 旧项目 121/123 个测试文件这么做 → 单进程 pytest 假失败 |
| 12 | 配置只从 `Settings` 读取，不得 `os.environ` 直读散落 | 旧项目 `.env` 写模型被 JSON **静默覆盖** |
| 13 | **节点不得原地修改 state 对象** | ⚠️ `langgraph#8314` 状态通道**引用透传** → 原地改会**污染调用方输入**（静默数据损坏） |
| 14 | **并行分支不得写同一状态键** | ⚠️ `langgraph#8115` 并行写竞态**静默丢 checkpoint**（30/30 复现） |
| 15 | 时间字段必须存 **UTC ISO8601 字符串**，不得用 `datetime` 对象过 checkpoint | ⚠️ `langgraph#8826` datetime **静默丢时区** |
| 16 | **每个 LLM 节点必须有幂等键** `(book_id, chapter_no, node_name, attempt_no)` | ⚠️ `langgraph#7417`（53 评论 open）：>180s 调用被**静默重放** → 2~3× 冗余成本。旧项目 `editor` 平均 **117s**，章节生成极易超阈值 |
| 17 | **每个写出的信号必须有读取点**（`must_*` / `needs_*` / `*_flags`） | ⚠️ 旧项目 `must_review` **25 处写入 0 处读取** → 整条文风控制链失效 |
| 18 | 每个 prompt 中的数量/结构要求必须有校验器与测试 | 旧项目 `entry_state` 13%、`milestone_ids` 0%、`conflict_curve` 从不校验 |
| 19 | 正文/细纲 JSON 不得进入图 State | 防 checkpoint 膨胀（官方 5.3 GB 案例） |
| 20 | 无 `LANGSMITH_*` 环境变量时系统必须完全可用 | 防 SaaS 锁定；用户要求"评测后续再加" |

**实现**：`tests/contract/test_architecture_invariants.py`，用 `ast` 模块静态扫描。
**CI 门禁**：任一条失败即阻断合并。
