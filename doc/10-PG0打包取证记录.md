## 2. 取证一：wheel 文件清单（93 项）

**实测 wheel 内容**（`zipfile.namelist()`，共 **93** 项）：

- ✅ 源码：`storyforge/**.py`（含 `api/`、`domain/`、`graph/`、`infra/`、`modes/`、`scorecard/`、`observability/`）
- ✅ prompt 模板 **3 个 md**：`extract_scene.md`、`style_critic.md`、`writer_system.md`
- ✅ `entry_points.txt`：`storyforge = storyforge.cli:main`
- ❌ **`config/` 一个都没有** —— **0** 个 `.toml`

### ★ B-6（新发现）：`config/` 完全没进 wheel

| 对比 | 结果 |
|---|---|
| **wheel**（`py3-none-any`，实际安装用这个） | `config/` 条目 **0** |
| **sdist**（`.tar.gz`，源码分发用） | `config/` 条目 **64** |

**根因**：`pyproject.toml` 只声明了

```toml
[tool.hatch.build.targets.wheel]
packages = ["src/storyforge"]
```

而 `config/` 位于**仓库根**、**不在 `src/storyforge` 包内** → hatchling 打不进 wheel。
sdist 会带上它，是因为 sdist 默认收整个项目树 —— 所以**"sdist 里有"不等于"wheel 里有"**。

**受害范围**（全部 `load_*` 都会失败或静默为空）：
`config/providers.toml`、`config/scales.toml`、`config/settings.toml`、
`config/genres/*.toml`（**18**）、`config/flows/xianxia/*.toml`（**25**）、
`config/flows/tropes/*.toml`（**16**）、`config/mappings/*`（**2**）。

### 更正：prompt md 是 **3** 个，不是 4 个

`doc/08` §4 写「4 个 md」。**实测 `src/storyforge/infra/prompts/*.md` = 3 个**
（`extract_scene.md` / `style_critic.md` / `writer_system.md`）。
**并且没有 `learn/` pack 子目录** —— 即 `_load(name, pack="learn")` 在**任何**形态下都必然抛错
（这是步骤⑥ learn-C 尚未动工的正常结果，不是本阶段缺陷，但 `doc/08` 的"4 个"是错的）。

## 4. 取证三：安装版 `doctor` 与离线命令

### B-2 的直接后果：`doctor` FAIL

```
[OK  ] config                    data_dir=<venv>\Lib\data
[OK  ] structure_gate_enabled    ...
[OK  ] database                  15 tables
[OK  ] foreign_keys_forced       ...
[OK  ] integrity                 ok
[OK  ] all_tables_have_fk        ok
[FAIL] providers                 ProviderConfigError: 找不到 providers 配置：<venv>\Lib\config\providers.toml
[OK  ] domain_is_framework_free  ok
doctor: FAIL  (storyforge 0.1.0)      EXIT 1
```

### ★ 检查项从 10 项掉到 8 项（另 2 项**静默消失**）

| 形态 | `run_doctor()` 返回的检查项 |
|---|---|
| 源码树 | `config`、`structure_gate_enabled`、`database`、`foreign_keys_forced`、`integrity`、`all_tables_have_fk`、`providers`、`extractor_thinking_minimized`、`api_keys`、`domain_is_framework_free` = **10** |
| 安装版 | **8** —— 缺 **`extractor_thinking_minimized`**、**`api_keys`** |

**根因**：`doctor.py:90-125` 把 `providers` 与那两项**放在同一个 `try` 里**；
`load_registry()` 一抛，整个 `except` 只补一条 `providers` FAIL，
**后面两项根本没机会跑** → 用户看到的报告里它们**不存在**，
而不是"未检查"。这与本项目「**写出的信号无人读**」「**静默降级**」两条反模式同源。

### ★ B-5 实测：不是"误报"，是**静默假通过**

```
扫描路径: <venv>\Lib\src\storyforge     exists: False
其中 domain/*.py 命中: 0 个  -> 违规列表为空 -> 该项报 OK
```

`domain_is_framework_free` 在安装版**报 OK**，但它**一个文件都没扫**。
即：**源码树不存在时这条架构契约自动变成恒真**。

### ★ B-8（新发现）：`flows` 静默返回空，且**退出码 0**

```
$ storyforge flows -n xianxia
══ xianxia ══  修仙流派（25 个，源自旧项目 flows.py）
  （目录为空或不存在）
查看某流派完整卡：storyforge flows --detail <id> [--with-example]
EXIT 0
```

`load_namespace('xianxia')` 返回 **0 个**（真实应为 **25**），但**不报错、不退非零**。
用户会以为"这个项目就是没有流派"，而不是"资源没装进来"。
★ 这**直接命中本项目明令禁止的反模式**：「读不到就返回空 —— 旧项目 `read_chapter`
静默返回空串导致正文丢失不报错」。

### ★ B-7（新发现）：`doctor` 把 176KB 数据库写进**安装目录**

```
运行 doctor 前: <venv>\Lib\data 不存在
运行 doctor 后: <venv>\Lib\data\storyforge.db  (176,128 B) + artifacts/
根因: Settings.ensure_dirs() 对 data_dir 做 mkdir(parents=True, exist_ok=True)
```

**为什么这是硬阻塞**：真实安装目录是 `C:\Program Files\...`（**用户无写权限**）。
届时 `ensure_dirs()` 要么抛 `PermissionError`，要么在 UAC 虚拟化下**静默写到
`%LOCALAPPDATA%\VirtualStore`**（用户永远找不到自己的数据）。
`doctor` 本应是**只读体检**，却产生了**持久副作用**。
