## 核心结论速览

### 项目规模（实测，已纠正过一次）

| 范围 | 文件 | 行数 |
|---|---|---|
| **实际业务代码**（排除 `_pylibs`） | **358** | **95,471** |
| `backend/app/`（核心） | 122 | 50,358 |
| `backend/_pylibs/`（vendored，非项目代码） | 397 | 288,238 |
| `pipeline.py`（单文件） | 1 | **8,607** |

> ⚠️ 初始勘察给出的「312,628 行 / 755 文件」是**错的**（把 `_pylibs` 算进去了，且 PowerShell `Measure-Object` 漏计空行）。已按 §14.2 的口径规约纠正。

### 七个痛点的根因（均已实测定位）

| # | 痛点 | 根因一句话 |
|---|---|---|
| 1 | 伤势不恢复 | **架构缺失**：`architect` 看不到损伤、`VALID_BEATS` 无 heal、恢复靠 prompt 催促而 writer 必须服从细纲 → **恢复率实测 0%** |
| 2 | 实体/势力乱 | **三套类型词汇表冲突** → LLM 吐的「势力」被判非法降级「其他」→ 势力实体 **0 个**；关系表 **86.7% 是非人际关系** |
| 3 | AI味重 | 文风模块 `shadow: true`（只观测不阻断）+ `dialogue_floor=0.12`（12% 即合格）+ **记忆密度从 4.8% 衰减到 0.16%**（模型只能原地描摹） |
| 4 | 关系单一 | 与痛点 2 同源：人物-人物关系仅 **13.3%**，仅 18 个角色被追踪（400 章） |
| 5 | 长篇不丰满 | **多层代码显式禁止换图**（8 处）→ 全书仅 2~5 次换图许可；规划层无扩张 schema；**400 章全挤第 1 卷** |
| 6 | prompt 过多 | `post_processor` 单条 system **>10,000 字符**抽 11 类信息；全仓 prompt 文本 172,822 字符 |
| 7 | token/缓存 | 缓存命中 44%，但**成本占比仅 0.35%** —— 真正大头是 **output（含 reasoning）77.5%**；空输出率 **22.2%**；`finish_reason` **100% 未采集** |

### 最重要的三个"反直觉"发现

1. **缓存命中不是最大成本口子**：hit 占成本 **0.35%**、output 占 **77.5%**。且"砍 reasoning 长度"已被 74 条真实数据**证伪**（配置上限从未撞到）。
2. **痛点 5 不是能力问题而是设计禁止**：`architect.py` / `writer.py` / `editor.py` 共 8 处明文禁止换地图，唯一许可在卷首（全书 2~5 次）。
3. **最底层成因是信息预算恒定**：第 1 章与第 1500 章拿到的世界记忆一样多（约 1.2 万字），记忆密度衰减 **30 倍** → 模型只能把当下场景反复描摹到字数达标。

### 并行流水线（D-13）

```
圣经 ─[C-1]→ 骨架批1 ─[C-2]→ 骨架批2 → 骨架批3 ...
                │              │
                └→ 细纲批1 ────┴→ 细纲批2 → ...        ← 与骨架并行
                       │
                 第1章细纲就绪
                       │
                  [C-3] → 正文1 → 正文2 → ...           ← 与细纲并行
                            │
                        [C-5 黄金三章]
```

**为什么不是一个大图**：单图的两个分支里，`interrupt()` 会**冻结整个图** ——
确认首章细纲时骨架/细纲生产也被冻住，并行就没了。
因此 LangGraph 图降为「工作单元」，由纯 Python 协调器调度（每单元一个 `thread_id`，崩溃恢复更精确）。

## 补充风险（D-13 引入）

| 风险 | 说明 | 缓解 |
|---|---|---|
| **协调器成为新的复杂度中心** | 纯 Python 编排器若不加约束，可能重演 `pipeline.py` 的臃肿 | ① 协调器**不含领域逻辑**（反模式检查：`grep -r "asyncio" domain/` 返回空）；② 单函数 ≤200 行、单文件 ≤800 行（反模式第 10 条）；③ P0-8 用哑 worker 先验证骨架 |
| **多 worker 并发写 DB** | SQLite 并发写入限制 | ① 阶段内串行（worker 数=1）；② WAL 模式；③ 单写入者原则：正文/细纲/骨架写**不同的表**，无跨 worker 写冲突 |
| **三级重叠导致问题难定位** | 出问题时不知是骨架、细纲还是正文的错 | ① 每个工作单元有独立 `thread_id` 与日志；② 三层产物全部落库可回查；③ 干跑模式（只规划不写作）用于隔离 |
