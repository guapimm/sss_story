## 0. 一页摘要

### 0.1 要解决的问题

PG-0 实测：**非 editable 安装后系统基本不可用** —— `providers` / `prompts` / `config`
三条链路同时断。共 **8 个阻塞点**，但**根因只有 3 个**：

| 根因 | 阻塞点 | 一句话 |
|---|---|---|
| **R1 `config/` 没进 wheel** | B-6（并连带 providers FAIL、flows 空） | `pyproject.toml` 只声明 `packages = ["src/storyforge"]`，而 `config/` 在仓库根 |
| **R2 路径锚点错** | B-1、B-2、B-3、B-4、B-5 | `REPO_ROOT = parents[2]` 与 `PROMPTS_DIR` 拼 `src/` 在安装态双双失效 |
| **R3 静默降级** | B-5 假通过、B-8 空流派、doctor 丢 2 项 | 读不到就返回空/报 OK，命中本项目明令禁止的反模式 |

### 0.2 分三个阶段（各自可独立验收、独立回滚）

| 阶段 | 一句话 | 核心验收判据 |
|---|---|---|
| **PG-1A** 资源定位统一 | 让 `config/` 与 `prompts/` 在**两种形态**下都能定位 | 隔离安装后 `doctor` **10 项 PASS**、三个 prompt 可读、流派 25/16、题材 18 |
| **PG-1B** 数据目录与副作用 | 安装态数据落用户可写目录；`doctor` 不再写盘 | 运行 `doctor` 后**安装目录文件增量为 0** |
| **PG-1C** 消除静默降级 | 读不到就大声报错，不伪装成"通过" | **变异测试**证明三种退化都被拦下 |

### 0.3 推荐方案（详见 §3.2 的甲乙对比）

**方案甲：`force-include`** —— `config/` 留在仓库根，构建时映射进包。
**源文件移动 0 个**，源码树所有既有路径与测试断言**完全不变**。
（方案乙"移入包内"要动 64 个文件 + 3 个移植脚本 + conftest + 多个测试，代价高一个数量级。）

## 2. ★★ 推敲中发现并已消解的设计陷阱

这一节是本计划的核心价值 —— 这些是"如果直接照着直觉改，会做出错误修改"的地方。

### 2.1 陷阱一：`storyforge/config/` 与 `storyforge/config.py` **同名冲突**

最直觉的做法是 `git mv config src/storyforge/config`。**实测这会坏**：

```
mypkg/config.py              ← 模块
mypkg/config/providers.toml  ← 同名目录
import mypkg.config  →  解析到 config.py（模块优先），该对象没有 __path__
```

即"目录里明明有文件，代码却读不到" —— **与 B-1 现在的症状一模一样**。
**结论**：包内资源目录**绝不能叫 `config`**，必须用 `_resources` / `_data` 之类的名字。

> 这直接决定了 §3.2 方案乙的成本（要连带改 3 个移植脚本与文档里的路径描述），
> 也强化了**方案甲**的推荐。

### 2.2 陷阱二：`load_namespace` 返回空是**被测试锁定的正当行为**

`tests/unit/test_mode_data.py:415-419`：

```python
def test_missing_namespace_dir_returns_empty(tmp_path, monkeypatch) -> None:
    """命名空间目录不存在 → 空 dict（全新 clone 时可能尚未填充）。"""
    assert load_namespace("tropes") == {}
```

**因此 B-8 的修法不能是"让 `load_namespace` 抛错"** —— 会破坏一条**有正当理由**的测试
（全新 clone 尚未跑 `port_flows.py` 时确实是空的）。
**正解**：数据层语义保持 `{}` 不变，在**用户可见层**（`cmd_flows`、`doctor`）把
"资源整体缺失"与"命名空间为空"**区分开并大声报错**。

### 2.3 陷阱三：`REPO_ROOT` 有**双重用途**，不能简单删除

| 使用处 | 用途 | 安装态是否有意义 |
|---|---|---|
| `cli.py:70` | `arch-check` 的 `cwd`（跑 `tests/contract`） | ❌ B-4 |
| `cli.py:444` | 提示 `.env` 位置 | ❌ B-3 |
| `doctor.py:147` | 扫 `src/storyforge` 判分层纪律 | ❌ B-5 |
| `tests/unit/test_dotenv.py:119,130,141` | 断言 `.env`/`.env.example`/`.gitignore` 在**仓库根** | ✅ **仅源码树** |

**结论**：`REPO_ROOT` 要**保留"源码树时为仓库根"的语义**（否则那三个测试与开发命令失效），
但关键路径**不得再依赖它**。做法是引入**资源定位函数**，让 `REPO_ROOT` 退化为
"开发期辅助"，而非资源根。

### 2.4 陷阱四：`DEFAULT_CONFIG_DIR` 是**模块级常量**，在 import 期求值

`config.py:37` 的 `DEFAULT_CONFIG_DIR = REPO_ROOT / "config"` 在 **import 时**就算好了。
若只把 `REPO_ROOT` 改成函数，`DEFAULT_CONFIG_DIR` 仍会**冻结**在 import 期的值上
→ 运行期改环境变量无效。**必须**把两者都改为**函数式/属性式**按需解析。

### 2.5 陷阱五：改 `config_dir` 有**契约边界**要确认（已核实无冲突）

- `modes/` 层已在 import `storyforge.config`（`flows.py:43`、`genres.py:35`、
  `mappings.py:32`、`scales.py:30`）→ 改 `config.py` **不新增跨层依赖**。
- 契约规则 3 扫描 `src/storyforge/` 但**豁免 `modes/`**（`test_architecture_invariants.py:164`）
  → 无冲突。
- 四个 `modes/` 加载器都是**调用期**取 `get_settings().config_dir`（非 import 期）
  → 改为函数式解析**天然兼容**。
- 唯一的 `lru_cache` 在 `scales.py:91`，键含 `path_str` + `mtime_ns` → **路径变了会自动失效**，无脏缓存风险。

### 2.6 陷阱六：`scripts/` 下 40+ 处 `parent.parent` **不需要动**

全仓扫描确认：除 `config.py:35` 外，所有 `parents[N]` / `parent.parent` 都在 `scripts/`
（dev-only，**从不随包分发**）。**本阶段明确不动 `scripts/`**，避免无谓扩大改动面。

### 2.7 陷阱七：测试通过 `conftest.py` 显式注入 `config_dir`，回归面可控

`tests/conftest.py:36`：

```python
config_dir=Path(__file__).resolve().parents[1] / "config",
```

→ 测试**不依赖**默认 `config_dir`；且全仓**没有任何测试** monkeypatch
`flows_dir`/`genres_dir`/`scales_path`（已实测为 0 命中）。
**含义**：只要保持"源码树默认仍解析到 `REPO_ROOT/config`"，**1083 条测试零影响**。

### 2.8 陷阱八：并行 agent 正在同一工作树运行

PG-0 期间实测：另一 agent 在 `data/s0_probe/` 跑真实 S0 取证。
**开工前必须确认其已收敛**（见 §7）。

## 3. PG-1A：资源定位统一

### 3.1 目标

非 editable 安装后：`providers.toml`、18 题材、25 流派、16 套路、2 映射、3 prompt **全部可读**。

### 3.2 待决策：两种打包方式

| | **方案甲 `force-include`（推荐）** | 方案乙 移入包内 |
|---|---|---|
| 做法 | `config/` **留在仓库根**；pyproject 加<br>`[tool.hatch.build.targets.wheel.force-include]`<br>`"config" = "storyforge/_resources/config"` | `git mv config src/storyforge/_resources/config` |
| **源文件移动** | **0 个** | **64 个** |
| 需同步修改 | 仅 `config.py` 的解析逻辑 | 解析逻辑 **+ `port_flows.py`/`port_genres.py`/`port_scales.py`/`port_mapping_rules.py` + `conftest.py:36` + 文档** |
| 名称冲突风险 | 无（目标路径自带 `_resources`） | 需改名避开 `config.py`（§2.1） |
| 源码树路径 | **完全不变** | 全变，多处断言需跟进 |
| 缺点 | 仓库根保留 `config/`（布局"标准度"略低） | 更标准 |

**推荐甲**。理由：改动面小一个数量级，且**源码树零影响** ——
符合「最小完整改动」；`config/` 在仓库根本就是**数据与代码分离**（阶段 1 的设计意图）。

### 3.3 解析规则（两方案共用）

```
config 目录解析顺序（高 → 低）：
  1. STORYFORGE_CONFIG_DIR 环境变量          ← 既有能力，保持最高优先级
  2. <包内> storyforge/_resources/config      ← 安装态命中
  3. REPO_ROOT/config                         ← 源码树命中
```

`PROMPTS_DIR` 同构，锚点从 `REPO_ROOT / "src" / ...` 改为**本模块所在目录**
（`Path(__file__).resolve().parent`）—— PG-0 已实测该锚点在两态下都正确，
且 prompt **已在 wheel 内**，**无需任何额外打包配置**。

### 3.4 顺带修掉的既有缺陷（同一处改动，不另开任务）

| 项 | 位置 | 说明 |
|---|---|---|
| 配置来源不一致 | `capability.py:321` | 用模块常量 `DEFAULT_CONFIG_DIR` → 改 `get_settings().config_dir`，使 `STORYFORGE_CONFIG_DIR` 对 `providers.toml` 生效（PG-0 实测该缺陷真实存在） |
| 死导入 | `capability.py:32` | `REPO_ROOT` 被 import 但**从未使用**（已 grep 确认） |

### 3.5 验收判据（PG-1A）

**主判据必须在隔离 venv 里做**（复现 `doc/10` §6）：

1. `storyforge doctor` → **10 项 PASS**（当前为 8 项 + `providers` FAIL）
2. `_load('writer_system')` / `'extract_scene'` / `'style_critic'` **三个全部成功**
3. `load_namespace('xianxia')` == **25**；`'tropes'` == **16**
4. `load_all_genres()` == **18**
5. 项目自身：`uv run pytest` 仍 **1083 passed / 15 skipped**；`doctor` 仍 PASS
6. ★ **变异验证**：从 wheel 移除 `_resources/config` → 判据 1/3/4 **必须失败**
   （证明断言真的在读资源，不是恒真）

## 4. PG-1B：数据目录与 `doctor` 写副作用

### 4.1 问题（PG-0 实测）

- 安装态 `data_dir` = `<venv>\Lib\data` → 真实装到 `C:\Program Files` 会
  `PermissionError`，或在 UAC 虚拟化下**静默写进 VirtualStore**（用户找不到自己的作品）。
- `doctor` 本应是**只读体检**，却创建了 **176,128 B 的 `storyforge.db`**
  （根因：`doctor.py:48` 的 `ensure_dirs()` + 打开数据库）。

### 4.2 修法

```
data 目录解析顺序：
  1. STORYFORGE_DATA_DIR 环境变量              ← 保持最高
  2. 源码树（候选根有 pyproject.toml）→ REPO_ROOT/data
  3. 安装态 → 用户目录
       Windows : %APPDATA%\storyforge
       macOS   : ~/Library/Application Support/storyforge
       Linux   : $XDG_DATA_HOME/storyforge 或 ~/.local/share/storyforge
```

★ **硬约束：只在"安装态"切换**。若无条件改默认值，会**移动开发机上的 `data/`**
（现含 `artifacts/books/*`、`research_cache.json`、`_no_cache.json`、`s0_probe/`），
并破坏所有既有测试的默认路径假设。

### 4.3 `doctor` 消除写副作用

- `doctor.py:48` 的 `s.ensure_dirs()` → 改为**只读探测**：目录不存在时检查**父目录可写性**，
  报"将创建于 X"而**不实际创建**。
- 数据库检查：DB 不存在时报「未初始化（运行 `init-db`）」，**不代建**。

### 4.4 验收判据（PG-1B）

1. 安装态首次运行 `doctor` → **PASS**，且 ★ **安装目录文件增量为 0**（PG-0 实测当前为 +2）
2. 源码树 `data_dir` **仍是 `REPO_ROOT/data`**（开发工作流与既有测试零变化）
3. 设 `STORYFORGE_DATA_DIR=<tmp>` → 生效
4. `uv run pytest` 仍全绿

## 5. PG-1C：消除静默降级

### 5.1 三个具体退化

| # | 退化 | PG-0 实测现状 | 修法 |

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| `config.py` 是全局单点 | 改错 → **所有**资源加载失败 | 每步在隔离 venv 复验 `doc/10` §6；1083 测试 + `doctor` 双保险 |

| 无条件切 `data_dir` | 移动开发机数据、破坏测试 | §4.2 硬约束：仅安装态 |
| "skip 当通过" | 重演"全绿却不可用" | §5.2 skip 语义 + 变异测试 |
| 与并行 agent 冲突 | 互相覆盖 | §7 |

**回滚策略**：三个子阶段各自一个提交；任一阶段失败 → `git revert` 该提交即回到上一稳定态。
